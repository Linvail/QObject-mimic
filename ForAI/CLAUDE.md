# QObject-mimic

## Purpose & scope

A lightweight, Qt-QObject-style signal/slot + cross-thread event-queue library in C++17
(github.com/Linvail/QObject-mimic). Most of `technology/` was originally generated by Gemini and
should not be trusted uncritically -- it has had real crash/UAF/leak/race defects.

**Explicit scope, in the owner's words:** "the cross-thread queued signal-and-slot system, plus
deleteLater and callLater. I don't want to provide a full Qt-like event system." Concretely: no
arbitrary user-postable events, no event filters, no public event-injection API. When evaluating
a change, ask whether it grows that surface back — if so, flag it rather than adding it.

## Architecture

- `GObject` — base class. `connect()`/`callLater()` (many SFINAE overloads for member fn /
  overloaded member fn / functor / free fn / signal targets), thread affinity
  (`moveToThread()`/`thread()`/`threadData()`), `deleteLater()`, `startTimer()`/`killTimer()`.
- `GSignal<Args...>` — thin wrapper over `boost::signals2::signal`.
- `GThread` — `std::thread` wrapper owning a `GThreadData` (atomic dispatcher pointer + owns-flag);
  `run()`/`exec()` drives the event loop by looping `dispatcher->processEvents()`.
- `GAbstractEventDispatcher` / `GEventDispatcherDefault` — the actual event queue, timer list, and
  condition-variable wait loop. `GEventDispatcherWin32`/`Linux` currently just inherit
  `GEventDispatcherDefault` unchanged (no native message-loop integration yet).
- `GTimer` — user-facing wrapper over `startTimer`/`killTimer` + a `timeout` signal.
- `GCoreApplication` — owns the main thread's dispatcher; `exec()`/`quit()`.

## Build & test

- Build system is `waf` (see `wscript` / `tests/wscript`, target name `Tests`). Confirm the exact
  invocation for this checkout rather than assuming a flag — ask if unsure.
- Debug builds enable AddressSanitizer by default (`tools/toolchain-linux.py`). Always prefer the
  debug/ASan config when testing — several tests in `tests/test_defect_regressions.cpp` rely on
  ASan/LeakSanitizer to give a hard signal, not just their own assertions (see that file's doc
  comments for which ones and why).
- Tests use GoogleTest, live in `tests/*.cpp`.

## Status

1. **Defect review + fixes: done, verified.** `technology/G*.{h,cpp}` reviewed for crash/UAF/leak/
   race defects; 7 found and fixed (data races on `GObject::m_threadData` and
   `GThreadData::ownsDispatcher`, `~GObject()` invalidating its life token too late,
   `GThread::start()` calling `std::terminate()` on restart, a use-after-free in
   `GEventDispatcherDefault::processEvents()`'s dispatch loop, a stale `wait_for()` timeout
   starving newly-registered shorter timers, a `GTimerEvent` leak on `interrupt()`). Full
   rationale in `CHANGES.md`. Owner built + ran `Tests` on Windows and WSL2 Ubuntu 22.04: no
   failures, ASan reported no leaks.
2. **Regression tests: done.** `tests/test_defect_regressions.cpp`. Mix of deterministic tests and
   honestly-labeled best-effort stress tests — some of the underlying races are only a few CPU
   instructions wide and can't be forced from a black-box test; read each test's doc comment
   before assuming a clean run proves more than it does.
3. **API surface reduction ("fuller cut") + cleanup-callback deadlock fix: in progress.** See
   `CURRENT_TASK.md` (imported below) for exact scope and what's left.

## Conventions

- 4-space indent, Allman braces, doxygen (`/** @brief ... */`) on every new function/type — match
  existing style.
- C++17 only, not C++20.
- Prefer minimal, targeted edits over rewrites. The `connect()`/`callLater()` template-overload
  boilerplate in `GObject.h` is large and repetitive by design (SFINAE dispatch on slot shape) —
  don't "clean it up" incidentally.
- Not-yet-fixed issues live in `CHANGES.md`'s "PS — noted but not patched" section. Don't fold
  them into an unrelated task without flagging it first; they're bigger design changes the owner
  hasn't scoped yet.
