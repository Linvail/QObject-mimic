# QObject-mimic defect fixes

Patch: `qobject-mimic-defect-fixes.patch` (unified diff, `git apply`/`patch -p1` compatible,
relative to `technology/`). Full corrected copies of the 5 touched files are included alongside
it for easy side-by-side review.

All fixes verified with `g++ -std=c++17 -fsyntax-only -Wall -Wextra` (real Boost headers weren't
available in the sandbox, so a minimal `boost::signals2` stub was used purely for parsing —
logic/semantics were reviewed by hand, not exercised at runtime). Please still run your existing
gtest suite before merging.

## technology/GObject.h / GObject.cpp

**1. Data race on `GObject::m_threadData`.**
`m_thread` was made atomic but its sibling `m_threadData` (`shared_ptr<GThreadData>`) was a plain
member, written by `moveToThread()` and read — unsynchronized — from `threadData()`,
`startTimer()`, `killTimer()`, `deleteLater()`, `dispatchMetaCall()`, and `~GObject()`, all
documented thread-safe. Concurrent unsynchronized read/write of a `shared_ptr` is undefined
behavior. Added `mutable std::mutex m_threadDataMutex` guarding every access; `startTimer()`,
`killTimer()`, and `deleteLater()` now go through the `threadData()` accessor instead of touching
the member directly.

**2. `GThreadData::ownsDispatcher` was a plain `bool`** mutated from the owning thread's start
lambda and read from `setEventDispatcher()` (any thread). Changed to `std::atomic<bool>`.

**3. `~GObject()` reset the life token (`m_life`) last**, after running cleanup callbacks and
erasing pending call-laters — i.e. after executing arbitrary user code. Any `weak_ptr::lock()` in
a `connect()`/`callLater()` wrapper racing on another thread could still succeed during that
window, queue an event, and later be dispatched to freed memory. Moved `m_life.reset()` to the
very top of the destructor to shrink that window down to the intrinsic check-then-post race
(further tightening needs a shared lock between destruction and dispatch — see PS below).

## technology/GThread.cpp

**4. `start()` could call `std::terminate()`.** If a previous run finished but `wait()` was never
called, `m_thread` still held a joinable `std::thread`. Calling `start()` again reassigned
`m_thread`, destroying a joinable `std::thread` mid-flight (`std::terminate()` per the standard).
Now `start()` joins any existing joinable thread first.

## technology/GEventDispatcherDefault.h / GEventDispatcherDefault.cpp

**5. Use-after-free in `processEvents()`'s dispatch loop.** `eventsToProcess` is a flat snapshot
drained once per call. If a receiver had a `GDeferredDeleteEvent` queued before another event
also destined for it, dispatching the delete event deletes the receiver, and the loop's next
iteration calls a virtual function through the now-dangling pointer.
`removeEventsForReceiver()` (called from `~GObject()`) can't help — it only prunes the
dispatcher's live queue, not the already-copied local batch. Fixed by tracking receivers deleted
via `GDeferredDeleteEvent` earlier in the same batch and skipping (and freeing) any further
events targeting them, across both the queued-event and timer-event dispatch loops.

**6. Timers could fire far later than scheduled.** The `wait_for` predicate only checked
`!m_eventQueue.empty() || m_interrupt`. `registerTimer()`/`unregisterTimer()` called
`notify_all()`, but since the predicate didn't consider timers, a spurious wakeup would
re-evaluate to `false` and go back to sleep for the *remaining* duration of the original
(stale) timeout — e.g. registering a new 50ms timer while already asleep for an existing 10s one
would not fire until ~10s later. Added `m_timersChanged` (guarded by the existing `m_mutex`),
set by `registerTimer()`/`unregisterTimer()`, checked in the wait predicate, and cleared right
before waiting.

**7. Leak of `GTimerEvent`s on interrupt.** Expired timers get `new GTimerEvent(...)`'d into
`timerEventsToProcess` *before* the interrupt check. If `interrupt()` fires concurrently, the
function returns without ever handing those allocations to the dispatch loop, leaking them.
Now frees any already-allocated timer events on that path.

## Tests (`tests/test_defect_regressions.cpp`, `tests/wscript`)

Added `tests/test_defect_regressions.cpp` and wired it into `tests/wscript`'s `Tests` target.
Six gtest cases, one per defect above (defect #2, the `ownsDispatcher` race, is intentionally not
covered separately — see note below). They fall into two honest categories:

**Deterministic (reliable pass/fail, not scheduling-dependent):**
- `GThreadDefectTest.RestartAfterFinishWithoutWaitDoesNotTerminate` — defect 4. Restarts a thread
  after it finished without ever calling `wait()`; pre-fix this calls `std::terminate()` and
  aborts the whole test binary (that abort *is* the failure signal, not a normal `FAIL()`).
- `GEventDispatcherDefaultDefectTest.DeferredDeleteFollowedByQueuedEventInSameBatchDoesNotCrash`
  — defect 5 (the UAF). Made reliable, not racy, by blocking the worker thread's event loop
  inside a queued slot while both events are posted, guaranteeing they land in the same batch —
  same technique the existing `ReceiverDestroyedBeforeQueuedEventHandled` test already uses.
- `GEventDispatcherDefaultDefectTest.NewShorterTimerWakesPromptly` — defect 6 (stale
  `wait_for()` timeout). Uses generous timing margins (3000ms long timer vs. asserting the short
  50ms one fires within 1500ms) so it isn't flaky under normal CI scheduling jitter.

**Best-effort stress tests (the underlying defects are genuine data races or a few-CPU-instruction
timing window; a clean pass increases confidence but isn't a proof, and these are most useful run
under AddressSanitizer/ThreadSanitizer — this project's default debug build already enables
AddressSanitizer, see `tools/toolchain-linux.py`):**
- `GEventDispatcherDefaultDefectTest.InterruptDuringTimerCollectionStress` — defect 7 (timer
  event leak on interrupt). No portable way to land deterministically in that exact window from
  outside the class, so this widens it (many pre-expired timers) and races `interrupt()` against
  it across many trials. Real signal comes from LeakSanitizer (bundled with ASan on Linux)
  reporting nothing at process exit.
- `GObjectDefectTest.ConcurrentMoveToThreadAndThreadDataAccessStress` — defect 1 (`m_threadData`
  race). Hammers `moveToThread()`/`threadData()`/`startTimer()`/`killTimer()` concurrently from
  three threads for ~2000+ iterations.
- `GObjectDefectTest.ConcurrentEmitDuringDestructionStress` — defect 3 (life-token reorder). Note
  in its doc comment: on closer analysis the *specific* exploitable window (between
  `removeEventsForReceiver()` completing and `m_life.reset()` running) is only a few CPU
  instructions wide in *both* the old and new code, so this test can't reliably discriminate old
  vs. new by itself. What the reorder actually guarantees — `removeEventsForReceiver()` now
  always runs after the life token is invalidated within the same destructor call, giving it a
  chance to catch anything that slips through — is structural, not something 300 racing
  iterations can prove either way. Kept as a robustness stress test, documented honestly rather
  than overclaiming.

**Not separately tested:** defect 2 (`GThreadData::ownsDispatcher` race). Isolating a test for
just this without also exercising the neighboring, still-unpatched `setEventDispatcher()`/thread-
lifecycle TOCTOU race (noted above) turned out not to be practically possible — any test that
actually exercises `ownsDispatcher` concurrently with a thread's own start/stop would likely be
exercising that other, known issue instead, which would misleadingly look like *this* patch
failing. Flagging instead of shipping a misleading test.

**PS — noted but not patched (larger design changes, flagging for awareness):**
- `GThread::setEventDispatcher()` can `delete` a dispatcher that's still being used by a live
  `exec()`/`processEvents()` loop on the owning thread (raw pointer loaded once per iteration).
- `GEventDispatcherDefault::m_interrupt` has no reset path; reusing a custom dispatcher on a
  restarted `GThread` after `exit()`/`quit()` busy-spins at 100% CPU.
- `GObject::event()`'s filter loop and `~GObject()`'s cleanup-callback loop invoke user code
  while holding non-recursive mutexes — reentrant filter/callback registration self-deadlocks.
- `GObject::callLater()` can silently and permanently drop a call if the target's dispatcher
  isn't set up yet (event allocated then deleted, no retry, pending-map entry leaks until the
  object is destroyed).

Happy to patch any of these next if useful — wanted to keep this patch focused on the crash/UAF/
leak/race items from the review.

# API surface reduction ("fuller cut") + cleanup-callback deadlock fix

Applied directly to the working tree (no patch file this time). Scope was approved verbatim as
"do fuller cut plus the cleanup-callback deadlock fix", in response to a proposal to close off
the "full Qt-like event system" surface that isn't wanted — see the Purpose & scope section of
`ForAI/CLAUDE.md`. Both `Tests` (42 cases) and `Demo` build clean and pass on Windows/MSVC
(`waf install --project=Tests` / `--project=Demo`); **not yet re-run on WSL2/ASan** — worth doing
before you consider this closed, since that's where LeakSanitizer gives its signal.

## Rationale

The library only ever posts three event types, all from `GObject`'s own internals (`deleteLater`,
`startTimer`/`killTimer`, `dispatchMetaCall`). Everything below removes a way for outside code to
inject an event or timer *aimed at some other object*, which was the part of the surface that
made this look like a general event system rather than a queued signal/slot mechanism.

**1. Removed `GCoreApplication::postEvent()`.** Unused internally, and the only public way besides
`event()` itself to inject an arbitrary event for an arbitrary receiver.

**2. `GObject::event()` is now private and non-virtual** (was `public virtual`), with
`GEventDispatcherDefault` friended as its sole caller. It's internal dispatch plumbing, not an
extension point. `timerEvent()` remains public/virtual — that's the supported hook.

**3. `GObject::dispatchMetaCall()` is now private** (was `public static`). Only `connect()`/
`callLater()`'s own member-template bodies call it, and those are members of `GObject` regardless
of the caller's access level.

**4. `postEvent`/`registerTimer`/`unregisterTimer`/`removeEventsForReceiver` moved from `public`
to `protected` on `GAbstractEventDispatcher`, with `friend class GObject;`.** These are exactly
the receiver-targeting operations. `processEvents()`/`wakeUp()`/`interrupt()` stay public — they
drive or stop the loop but can't be aimed at a particular object. Mirrored on
`GEventDispatcherDefault`'s overrides too; the base class's access already governs calls through
the `GAbstractEventDispatcher*` that `GThread::eventDispatcher()` hands out, so that part is
belt-and-suspenders for anyone holding a `GEventDispatcherDefault*` directly.

**5. Removed the event-filter subsystem entirely** — `installEventFilter`/`removeEventFilter`/
`eventFilter()`, the `m_eventFilters`/`m_eventFilterMutex` members, and the filter loop in
`event()`. This was a hazard in its own right, not just surface: a filter sitting in front of
*every* event type could silently swallow a `deleteLater()` or a queued signal delivery.

**6. Removed `GObject::customEvent()`.** Its one real job — routing `GEvent::MetaCall` to
`GMetaCallEvent::placeMetaCall()` — is now inlined into `event()`'s switch, and the `default:`
branch returns `false` instead of forwarding to a user hook.

**7. Fixed the cleanup-callback deadlock in `~GObject()`** (the third PS item above; its
event-filter half is moot now that filters are gone). The callbacks were invoked while
`m_cleanupMutex` was still held, so a callback calling `addCleanupCallback()` on the same object
relocked a non-recursive mutex. Now the vector is swapped out under the lock and the copies run
with it released. A callback registered *during* that loop is intentionally dropped — the object
is already being destroyed, so there's no later point at which it could run — documented in a
comment at the call site.

`GEvent::User`/`None` were left in the enum. They're unreachable dead code now that nothing can
post an arbitrary event, but pruning them wasn't in the approved scope. Say the word if you want
them gone too.

## Ripple effects

- `tests/test_gobject.cpp`: removed the `GObjectTestFilter`, `CustomTestEvent`, and
  `CustomEventReceiver` helper classes plus the `EventFilterInterception`,
  `EventFilterRemovalAndBypass`, and `CustomEventHandling` cases — all tested removed APIs.
- `src/main.cpp` (Demo): removed the `TestEventFilter` class and the `[Test 5]` event-filter
  block. Note the `GObject targetObject;` declared in that block is **kept** — the GTimer and
  WorkerThread sections below it still use it as their context object. Nothing depends on the
  `[Test 5]` label, so no renumbering.
- `tests/test_defect_regressions.cpp`: `InterruptDuringTimerCollectionStress` called
  `dispatcher.registerTimer()` directly on a raw `GEventDispatcherDefault`, which change 4 makes
  inaccessible. Rather than weaken the shipping class or put a gtest-generated class name in a
  production header, the test now instantiates a local `DefectTestableDispatcher` subclass that
  re-widens access with `using GEventDispatcherDefault::registerTimer;`. The test body and its
  race window are otherwise unchanged.

## Verification

Beyond the suite passing, the cut was checked with 11 negative-compile probes confirming each
removed/narrowed API is now genuinely inaccessible from outside (private `event()` and
`dispatchMetaCall()`; deleted `installEventFilter`/`removeEventFilter`/`eventFilter`/
`customEvent`/`GCoreApplication::postEvent`; protected `postEvent`/`registerTimer`/
`removeEventsForReceiver` through both a base and a concrete dispatcher pointer). All 11 fail to
compile; a positive-control probe exercising the surface that was meant to survive
(`timerEvent` override, `startTimer`/`killTimer`/`deleteLater`, `processEvents`/`wakeUp`/
`interrupt`, `GTimer`) still compiles.

## Tests

Added `GObjectDefectTest.CleanupCallbackRegisteringAnotherDoesNotDeadlock` for change 7 — the one
item here with runtime behavior to regress rather than just an access level. Verified to have
teeth by temporarily restoring the old destructor body: MSVC's `std::mutex` detects the recursive
lock and aborts the binary (exit 3), so on that toolchain the abort is the failure signal, the
same way `RestartAfterFinishWithoutWaitDoesNotTerminate`'s `std::terminate()` is. The destruction
runs on its own thread behind a 5s timeout to catch implementations that plain deadlock instead.
Both manifestations are written up in the test's doc comment.

**PS — still open from the previous list** (unchanged by this work): the
`GThread::setEventDispatcher()` TOCTOU double-delete, `m_interrupt` having no reset path
(100% CPU spin on dispatcher reuse — worth noting this one collides with the mission's own
"100% cpu-spin is not allowed" constraint for the dispatcher stage), and `callLater()` silently
dropping a call when the target's dispatcher isn't set up yet.

# Second pass: encapsulate thread data, drop setEventDispatcher, internalise event types

Follow-up audit of what was still reachable from outside once stages 6 and 7 (event filters, full
event system) were taken off the roadmap. Four items, all applied and verified on Windows/MSVC
and WSL2/GCC+ASan (42 tests, exit 0, no LeakSanitizer output).

**1. `GThreadData`'s members are now private,** with `friend class GObject; friend class GThread;
friend class GCoreApplication;`. This was the biggest remaining hole and strictly worse than
anything the first pass closed: the struct was public with public mutable atomics, handed out by
the public `threadData()` on both `GObject` and `GThread`, and the `shared_ptr` you got back
aliased the real per-thread state. Two one-liners were possible from outside the library —
`o.threadData()->dispatcher.store(garbage)` (a live `exec()` loop then calls through it) and
`o.threadData()->ownsDispatcher.store(true)` (thread exit deletes a dispatcher it doesn't own,
double-freeing `GCoreApplication`'s `unique_ptr`-held one). `threadData()` itself stays public and
simply becomes an opaque handle. No caller outside those three classes ever dereferenced it.

**2. Removed `GThread::setEventDispatcher()`,** which resolves PS item 1 outright: it could
`delete` a dispatcher that a running `exec()`/`processEvents()` loop on the owning thread was
still calling into (raw pointer re-loaded once per iteration). A thread now creates and owns its
dispatcher in `start()`, `GCoreApplication` supplies the main thread's, and `eventDispatcher()`
is read-only. This does **not** block the platform-dispatcher stage of the mission — the library
still selects `GEventDispatcherWin32`/`Linux` internally in `GThread::start()`; what's gone is
only the ability for outside code to swap one in on a live thread.

**3. Internalised the event hierarchy.** `GEvent`'s constructor is now `protected` (it is purely a
base class), `GMetaCallEvent`'s constructor *and* `placeMetaCall()` are private with
`friend class GObject` (it wraps an arbitrary callable — constructing or firing one is a real
capability), and `GDeferredDeleteEvent`'s constructor is private with the same friend (delivering
it destroys the receiver). The dead `GEvent::None` and `GEvent::User` enumerators are gone, so the
event set is now exactly the three types the queue actually carries.

`GTimerEvent`'s constructor is deliberately left public and documented as such: `timerEvent()` is
a supported override point, so synthesizing one to drive an override directly — which
`GTimerTest.ManualTimerEventTriggering` does — is legitimate, and it confers no capability since
it cannot be posted to any queue.

**4. `GObject::GCallLaterKey` / `GCallLaterKeyHash` are now private.** They are pure `callLater`
dedup internals. The blocker was `GObject.cpp`'s file-scope `s_pendingCallLaters` map, which has
to name both types; a plain file-scope map can't reach private nested types. Rather than leak
`<unordered_map>` and an internal member into the header, the map and its mutex moved into a
`GCallLaterRegistry` struct declared only in the `.cpp` and befriended by `GObject`. Behaviour is
unchanged — same map, same locking, just reachable only from the one translation unit that owns
it.

## Deliberately left public

- `GObject::objectLife()` — hands out the internal lifetime token, but it is the closest thing
  this library has to `QPointer` and is plausibly useful to callers. Flagged rather than changed.
- `GTimerEvent`'s constructor — see item 3.

## Ripple effects

- `tests/test_gthread.cpp`: `EventDispatcherSetAndGet` drove the removed setter and is replaced by
  `EventDispatcherOwnedAcrossThreadLifecycle`, which asserts the new contract instead — no
  dispatcher before `start()`, one present while running, clean shutdown after `quit()`/`wait()`
  (with ASan/LSan covering the leak-or-double-free half).
- Nothing else needed changing: no other caller outside `GObject`/`GThread`/`GCoreApplication`
  touched `GThreadData`'s members, and no test constructed a `GMetaCallEvent`,
  `GDeferredDeleteEvent`, or bare `GEvent`.

## Verification

The probe suite from the first pass was extended to 21 cases and re-run. All 11 original
negative probes still fail to compile (no regression) and the positive control still builds. Of
the 10 new probes covering this pass, 8 are now blocked — dispatcher hijack, forged
`ownsDispatcher`, `setEventDispatcher`, `GCallLaterKey`/`Hash`, `GMetaCallEvent` construction and
firing, `GDeferredDeleteEvent` construction, bare `GEvent` construction, `GEvent::User` — and the
2 that remain reachable are the two documented above as intentional.

**PS — still open:** `m_interrupt` has no reset path (100% CPU spin if a dispatcher is reused
after `exit()`/`quit()`; collides with the mission's own "100% cpu-spin is not allowed"
constraint), `callLater()` can silently drop a call when the target's dispatcher isn't up yet,
`GTimer`'s `m_interval`/`m_timerId`/`m_singleShot`/`m_active` are non-atomic and unguarded while
every accessor's doxygen claims "Thread-safe", and three of the six `GTimer` tests contain no
assertions at all (so the static `singleShot()` path is effectively unverified).
