# QObject-mimic defect fixes

Patch: `qobject-mimic-defect-fixes.patch` (unified diff, `git apply`/`patch -p1` compatible,
relative to `technology/`). Full corrected copies of the 5 touched files are included alongside
it for easy side-by-side review.

All fixes verified with `g++ -std=c++17 -fsyntax-only -Wall -Wextra` (real Boost headers weren't
available in the sandbox, so a minimal `boost::signals2` stub was used purely for parsing —
logic/semantics were reviewed by hand, not exercised at runtime). Please still run your existing
gtest suite before merging.

## technology/GObject.h / GObject.cpp

**1. Data race on `GObject::m_threadData`.**
`m_thread` was made atomic but its sibling `m_threadData` (`shared_ptr<GThreadData>`) was a plain
member, written by `moveToThread()` and read — unsynchronized — from `threadData()`,
`startTimer()`, `killTimer()`, `deleteLater()`, `dispatchMetaCall()`, and `~GObject()`, all
documented thread-safe. Concurrent unsynchronized read/write of a `shared_ptr` is undefined
behavior. Added `mutable std::mutex m_threadDataMutex` guarding every access; `startTimer()`,
`killTimer()`, and `deleteLater()` now go through the `threadData()` accessor instead of touching
the member directly.

**2. `GThreadData::ownsDispatcher` was a plain `bool`** mutated from the owning thread's start
lambda and read from `setEventDispatcher()` (any thread). Changed to `std::atomic<bool>`.

**3. `~GObject()` reset the life token (`m_life`) last**, after running cleanup callbacks and
erasing pending call-laters — i.e. after executing arbitrary user code. Any `weak_ptr::lock()` in
a `connect()`/`callLater()` wrapper racing on another thread could still succeed during that
window, queue an event, and later be dispatched to freed memory. Moved `m_life.reset()` to the
very top of the destructor to shrink that window down to the intrinsic check-then-post race
(further tightening needs a shared lock between destruction and dispatch — see PS below).

## technology/GThread.cpp

**4. `start()` could call `std::terminate()`.** If a previous run finished but `wait()` was never
called, `m_thread` still held a joinable `std::thread`. Calling `start()` again reassigned
`m_thread`, destroying a joinable `std::thread` mid-flight (`std::terminate()` per the standard).
Now `start()` joins any existing joinable thread first.

## technology/GEventDispatcherDefault.h / GEventDispatcherDefault.cpp

**5. Use-after-free in `processEvents()`'s dispatch loop.** `eventsToProcess` is a flat snapshot
drained once per call. If a receiver had a `GDeferredDeleteEvent` queued before another event
also destined for it, dispatching the delete event deletes the receiver, and the loop's next
iteration calls a virtual function through the now-dangling pointer.
`removeEventsForReceiver()` (called from `~GObject()`) can't help — it only prunes the
dispatcher's live queue, not the already-copied local batch. Fixed by tracking receivers deleted
via `GDeferredDeleteEvent` earlier in the same batch and skipping (and freeing) any further
events targeting them, across both the queued-event and timer-event dispatch loops.

**6. Timers could fire far later than scheduled.** The `wait_for` predicate only checked
`!m_eventQueue.empty() || m_interrupt`. `registerTimer()`/`unregisterTimer()` called
`notify_all()`, but since the predicate didn't consider timers, a spurious wakeup would
re-evaluate to `false` and go back to sleep for the *remaining* duration of the original
(stale) timeout — e.g. registering a new 50ms timer while already asleep for an existing 10s one
would not fire until ~10s later. Added `m_timersChanged` (guarded by the existing `m_mutex`),
set by `registerTimer()`/`unregisterTimer()`, checked in the wait predicate, and cleared right
before waiting.

**7. Leak of `GTimerEvent`s on interrupt.** Expired timers get `new GTimerEvent(...)`'d into
`timerEventsToProcess` *before* the interrupt check. If `interrupt()` fires concurrently, the
function returns without ever handing those allocations to the dispatch loop, leaking them.
Now frees any already-allocated timer events on that path.

## Tests (`tests/test_defect_regressions.cpp`, `tests/wscript`)

Added `tests/test_defect_regressions.cpp` and wired it into `tests/wscript`'s `Tests` target.
Six gtest cases, one per defect above (defect #2, the `ownsDispatcher` race, is intentionally not
covered separately — see note below). They fall into two honest categories:

**Deterministic (reliable pass/fail, not scheduling-dependent):**
- `GThreadDefectTest.RestartAfterFinishWithoutWaitDoesNotTerminate` — defect 4. Restarts a thread
  after it finished without ever calling `wait()`; pre-fix this calls `std::terminate()` and
  aborts the whole test binary (that abort *is* the failure signal, not a normal `FAIL()`).
- `GEventDispatcherDefaultDefectTest.DeferredDeleteFollowedByQueuedEventInSameBatchDoesNotCrash`
  — defect 5 (the UAF). Made reliable, not racy, by blocking the worker thread's event loop
  inside a queued slot while both events are posted, guaranteeing they land in the same batch —
  same technique the existing `ReceiverDestroyedBeforeQueuedEventHandled` test already uses.
- `GEventDispatcherDefaultDefectTest.NewShorterTimerWakesPromptly` — defect 6 (stale
  `wait_for()` timeout). Uses generous timing margins (3000ms long timer vs. asserting the short
  50ms one fires within 1500ms) so it isn't flaky under normal CI scheduling jitter.

**Best-effort stress tests (the underlying defects are genuine data races or a few-CPU-instruction
timing window; a clean pass increases confidence but isn't a proof, and these are most useful run
under AddressSanitizer/ThreadSanitizer — this project's default debug build already enables
AddressSanitizer, see `tools/toolchain-linux.py`):**
- `GEventDispatcherDefaultDefectTest.InterruptDuringTimerCollectionStress` — defect 7 (timer
  event leak on interrupt). No portable way to land deterministically in that exact window from
  outside the class, so this widens it (many pre-expired timers) and races `interrupt()` against
  it across many trials. Real signal comes from LeakSanitizer (bundled with ASan on Linux)
  reporting nothing at process exit.
- `GObjectDefectTest.ConcurrentMoveToThreadAndThreadDataAccessStress` — defect 1 (`m_threadData`
  race). Hammers `moveToThread()`/`threadData()`/`startTimer()`/`killTimer()` concurrently from
  three threads for ~2000+ iterations.
- `GObjectDefectTest.ConcurrentEmitDuringDestructionStress` — defect 3 (life-token reorder). Note
  in its doc comment: on closer analysis the *specific* exploitable window (between
  `removeEventsForReceiver()` completing and `m_life.reset()` running) is only a few CPU
  instructions wide in *both* the old and new code, so this test can't reliably discriminate old
  vs. new by itself. What the reorder actually guarantees — `removeEventsForReceiver()` now
  always runs after the life token is invalidated within the same destructor call, giving it a
  chance to catch anything that slips through — is structural, not something 300 racing
  iterations can prove either way. Kept as a robustness stress test, documented honestly rather
  than overclaiming.

**Not separately tested:** defect 2 (`GThreadData::ownsDispatcher` race). Isolating a test for
just this without also exercising the neighboring, still-unpatched `setEventDispatcher()`/thread-
lifecycle TOCTOU race (noted above) turned out not to be practically possible — any test that
actually exercises `ownsDispatcher` concurrently with a thread's own start/stop would likely be
exercising that other, known issue instead, which would misleadingly look like *this* patch
failing. Flagging instead of shipping a misleading test.

**PS — noted but not patched (larger design changes, flagging for awareness):**
- `GThread::setEventDispatcher()` can `delete` a dispatcher that's still being used by a live
  `exec()`/`processEvents()` loop on the owning thread (raw pointer loaded once per iteration).
- `GEventDispatcherDefault::m_interrupt` has no reset path; reusing a custom dispatcher on a
  restarted `GThread` after `exit()`/`quit()` busy-spins at 100% CPU.
- `GObject::event()`'s filter loop and `~GObject()`'s cleanup-callback loop invoke user code
  while holding non-recursive mutexes — reentrant filter/callback registration self-deadlocks.
- `GObject::callLater()` can silently and permanently drop a call if the target's dispatcher
  isn't set up yet (event allocated then deleted, no retry, pending-map entry leaks until the
  object is destroyed).

Happy to patch any of these next if useful — wanted to keep this patch focused on the crash/UAF/
leak/race items from the review.
